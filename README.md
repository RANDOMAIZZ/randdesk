# RandDesk

Удалённое управление своими ПК через веб-интерфейс: дашборд со статистикой, удалённая консоль,
диспетчер задач (процессы и службы), выполнение команд (в том числе сразу на нескольких ПК),
питание (выключение, перезагрузка, сон) и Wake-on-LAN.

Готовы этапы 0–5 плана, включая удалённый рабочий стол, а также подключение через интернет
и вход с двухфакторной аутентификацией (2FA).

## Быстрый старт (одной кнопкой)

1. На **главном ПК** запустите `randdesk.exe` двойным щелчком и разрешите установку.
   В браузере выберите «Главный ПК (администратор)», придумайте логин и пароль и нажмите **«Настроить ПК»**.
2. На **каждом другом ПК** сделайте то же самое, но выберите «Обычный ПК» и введите **тот же логин и пароль**.
   ПК сам найдёт главный в локальной сети (или в Radmin VPN) и подключится. Если главный ПК в другой сети,
   введите его внешний адрес на странице ожидания.

Адреса, ключи и команды не нужны. RandDesk ставится службой и запускается вместе с Windows.

Возможности администратора (на главном ПК):
- управление всеми ПК: рабочий стол, консоль, процессы, службы, команды, питание;
- **«Доступ»**: каким обычным ПК можно управлять какими. Без разрешения обычные ПК друг друга не видят;
  разрешённые ПК открываются на странице обычного ПК (http://localhost:8420);
- **отключение клавиатуры, мыши и геймпада** на любом ПК (на странице ПК). Удалённое управление
  через RandDesk при этом работает. Отключение сохраняется после перезагрузки, а клавиатуру и мышь главного ПК
  отключить нельзя;
- **единый буфер обмена**: текст, скопированный на одном ПК, вставляется на любом другом.

Безопасность: пароль по сети не передаётся. ПК доказывают друг другу знание пароля (HMAC от ключа scrypt),
а главный ПК проверяется по сертификату, полученному при первой привязке.

## Удалённый рабочий стол

Сделан с упором на минимальную задержку:

- захват через DXGI Desktop Duplication (GPU, кадр приходит сразу при изменении экрана), запасной вариант — GDI;
- экран делится на плитки 64×64, передаются только изменившиеся, JPEG кодируется параллельно на всех ядрах;
- не больше 2 кадров «в пути»: следующий кадр уходит после подтверждения отрисовки браузером,
  поэтому очередь не копится и на медленной сети растёт не задержка, а пропуск промежуточных кадров;
- курсор локальный (браузерный) — движение мыши без задержки; клавиатура по скан-кодам, не зависит от раскладки;
- полноэкранный режим перехватывает Win, Alt+Tab, Esc (Keyboard Lock API, Chrome/Edge);
- настройки: монитор, качество, разрешение 100/50 %, частота кадров; вставка текста; сочетания клавиш.

Захват выполняет отдельный процесс-помощник. Если агент работает службой, помощник запускается от SYSTEM
в активном сеансе пользователя — так виден и экран входа/UAC. На управляемом ПК во время сеанса
показывается красная плашка «этим ПК управляют удалённо» (в сам захват не попадает).

## Как устроено

```
браузер ──HTTP/WebSocket──► hub (веб-интерфейс + API) ◄──WebSocket── agent (на каждом ПК)
```

- Один файл `randdesk.exe`, роль задаётся командой: `hub` или `agent`.
- Агент сам подключается к хабу (исходящее соединение), входящие порты на управляемых ПК не нужны.
- Сеть — любая, где агент видит хаб: локальная, интернет, RadminVPN, ZeroTier, Tailscale.
- У агента может быть несколько адресов хаба. Он пробует их одновременно и выбирает первый
  по списку из доступных: дома подключается по локальной сети, вне дома — через интернет.
  Хаб сам сообщает агентам свои актуальные адреса (например, после смены внешнего IP).

## Доступ из интернета

Хаб принимает HTTP и HTTPS на одном порту (8420). Для HTTPS при первом запуске создаётся
самоподписанный сертификат (`data\hub-cert.pem`). Агенты проверяют хаб по отпечатку его ключа (`-fp`),
поэтому подменить хаб нельзя даже в чужой сети. Незашифрованный HTTP по умолчанию принимается только
из локальной сети и VPN (`-http lan`). Другие варианты: `-http all` или `-http off`.

Чтобы ПК подключались к хабу через интернет:

1. Включите **Настройки → Доступ из интернета → «Автоматически пробросить порт (UPnP)»**: хаб сам откроет
   порт на роутере и узнает внешний IP. Для этого в роутере должен быть включён UPnP.
   Если UPnP нет, пробросьте TCP-порт 8420 на ПК с хабом вручную в настройках роутера.
2. Если внешний IP меняется, заведите бесплатный домен DDNS (DuckDNS, No-IP или DDNS в самом роутере)
   и впишите его в поле «Свой внешний адрес».
3. Если у провайдера «серый» IP (CGNAT), проброс не поможет: хаб сообщит об этом. Тогда нужен
   VPN (Tailscale, ZeroTier, RadminVPN) или «белый» IP у провайдера.
4. Обязательно включите 2FA.

При открытии `https://` в браузере появится предупреждение о самоподписанном сертификате — это ожидаемо.
Свой сертификат (например, Let's Encrypt): `hub -tls-cert cert.pem -tls-key key.pem`; агентам тогда `-fp` не нужен.

## Вход, пользователи и 2FA

- Пользователей может быть несколько (Настройки → Пользователи), у каждого свой пароль и своя 2FA.
- 2FA — коды TOTP из любого приложения-аутентификатора (Google/Microsoft Authenticator, Яндекс Ключ, Aegis).
  При включении выдаются 10 одноразовых резервных кодов на случай потери телефона.
- Важные действия (выключение 2FA, новые резервные коды, добавление пользователя) требуют пароль и код.

## Сборка

Нужен Go 1.22+.

```powershell
.\build.ps1          # -> dist\randdesk.exe
```

## Запуск хаба

Проще всего запустить `randdesk.exe` двойным щелчком и выбрать пункт «Запустить хаб»:
откроется браузер с веб-интерфейсом. Хаб работает, пока открыто окно.
В том же меню есть подключение этого ПК к хабу и удаление агента.

Или из PowerShell:

```powershell
.\dist\randdesk.exe hub                  # слушает :8420, данные в dist\data
```

1. Откройте на этом же ПК http://localhost:8420 и создайте администратора
   (первичная настройка разрешена только с localhost).
2. Разрешите входящие подключения на порт 8420 в брандмауэре (PowerShell от администратора):
   ```powershell
   New-NetFirewallRule -DisplayName "RandDesk Hub" -Direction Inbound -Protocol TCP -LocalPort 8420 -Action Allow
   ```
3. Ключ привязки и готовые команды — кнопка «Добавить ПК» или «Настройки».

## Подключение ПК

Скопируйте `randdesk.exe` на ПК и выполните в PowerShell **от администратора**:

```powershell
.\randdesk.exe agent install -hub https://<локальный-IP>:8420,https://<внешний-адрес>:8420 -key RD-XXXX-XXXX-XXXX-XXXX -fp <отпечаток>
```

Готовую команду с адресами и отпечатком даёт кнопка «Добавить ПК».
Уже установленный агент (в том числе старой версии с `http://`) можно перевести на новые адреса
без повторной привязки — той же командой, но без `-key`:
`.\randdesk.exe agent install -hub https://...,https://... -fp <отпечаток>`.

Агент копируется в `C:\Program Files\RandDesk`, ставится службой `RandDeskAgent`
(автозапуск, перезапуск при сбое), конфигурация — `C:\ProgramData\RandDesk\agent.json`
(доступ только SYSTEM и администраторам), лог — `C:\ProgramData\RandDesk\agent.log`.

Для проверки без установки: `.\randdesk.exe agent -hub ... -key ...` (Ctrl+C — выход).
Удаление: `.\randdesk.exe agent uninstall`.

## Безопасность

- Вход в веб-интерфейс: пароль (bcrypt) + 2FA (TOTP, повтор кода не принимается), сессия в HttpOnly-cookie,
  ограничение попыток (отдельно для входа и для привязки ПК).
- HTTPS с закреплением сертификата у агентов; из интернета принимается только HTTPS.
- Защита от CSRF (обязательный заголовок), проверка Origin для WebSocket, CSP.
- Каждый ПК получает собственный токен при привязке; удалённый в интерфейсе ПК сразу отключается.
- Все действия (команды, консоль, процессы, службы, питание) пишутся в журнал (`data\audit.jsonl`).

## Ограничения текущей версии

- Агент работает от SYSTEM (как служба), поэтому консоль открывается от имени SYSTEM.
- Wake-on-LAN: magic-пакет отправляет хаб и все агенты в сети. Целевой ПК проснётся, только если хотя бы
  один из них находится в той же физической локальной сети, а WoL включён в BIOS/драйвере сетевой карты.
- Только Windows (хаб собирается и под Linux, агент — пока нет).

## Структура

```
cmd/randdesk      точка входа
internal/hub      сервер: API, сессии, хранилище, журнал, ретрансляция терминала
internal/agent    агент: статистика, ConPTY, процессы, службы, exec, питание, служба Windows
internal/proto    сообщения между хабом и агентом
internal/wol      Wake-on-LAN
internal/upnp     проброс порта на роутере (UPnP IGD)
web/static        веб-интерфейс (без сборки, встраивается в exe)
```
